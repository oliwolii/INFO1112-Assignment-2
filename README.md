## How to run
1. Create the container (from the host):
   `docker run -it --name myserver -p 1234:1234 alpine sh`
2. Install the tools (inside the container):
   `apk add bash curl html2text jq netcat-openbsd iproute2 python3 py3-matplotlib`
3. Copy the files in (from the host):
   `docker cp server.sh myserver:/root/` and `docker cp plot.py myserver:/root/`
4. Start the server (inside the container):
   `cd /root && bash server.sh`

On start-up the server prints its IP (found with `ifconfig`) and its listening port (found with `ss -ltnp`); neither is hard-coded in the output. It then listens with `nc -l` in an endless loop, one connection at a time, and prints `Connection received on <client IP> <port>` for every request.

Send requests from a second terminal **inside the container**, using the IP printed by the server:
`echo assignment | nc <server IP> 1234`

## Requests
| Request line | What happens |
|---|---|
| `assignment` (also `asssignment`) | `curl`s the unit page, converts it with `html2text`, prints the Assignment 2 row on the server terminal, then sends `assignment.json` to the client. All values are parsed from the page. |
| `population` | Downloads the ABS CSV, parses it with Bash/awk, prints the latest NSW population (2025), then sends `population.png` to the client. |
| `<POI name>` | Sends back JSON listing all POIs within 1000 m of that POI (NSW POI service). |
| `<latitude>,<longitude>` | Same, centred on those coordinates. |
| `slow` | Test helper: replies after 10 s (used for test case b). |

Any error (download failure, parse failure, unknown POI, service error, plot failure) is printed on the server terminal and sent to the client.

### POI request format
- **By name:** send only the name, in any letter case, e.g. `echo "Fisher Library Sydney University" | nc <server IP> 1234`. (The POI layer stores names in capitals, so the server upper-cases the request.)
- **By coordinates:** send `latitude,longitude` in decimal degrees (GDA94), **latitude first**, e.g. `echo "-33.8863,151.1905" | nc <server IP> 1234`. Anything of the form `number,number` is treated as coordinates; anything else as a name.
- **Distance:** "neighbouring" means within 1000 m; this is fixed in the server (`POI_DISTANCE_M`).
- **Output:** `{ "poi", "centre": {lat, lon}, "distance_m", "neighbours": [{name, type, lat, lon}], "truncated" }`. The service returns at most 1000 records per query; `truncated` is `true` if there were more.

## Test cases
- **(a) Server not running:** stop the server, then run `echo assignment | nc <server IP> 1234`. `nc` reports an error (connection refused) and exits with a non-zero status.
- **(b) Busy server:** run `echo slow | nc <server IP> 1234`, and within 10 seconds run the same command again from a second terminal. The server handles one connection at a time, so the second request is not served.

## Known limitations
- Test (b): with a plain `nc` listener the second connection is queued by the kernel and then dropped when the first request finishes, rather than being sent an explicit error message.
- A client that half-closes its connection right after sending (e.g. macOS `nc`) can lose slow replies such as `population.png`, because `nc -l` closes the connection when it sees the client's end-of-input. Running the client inside the container, as in the assignment examples, avoids this.
- The server needs the packages listed in "How to run".
